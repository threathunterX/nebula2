# ADR-0001:重写而非升级

- **状态**:已接受
- **日期**:2026-07

## 背景

Nebula 1.x 于 2019 年开源,主仓库获得 1000+ star、380+ fork,是国内开源业务风控领域少有的完整实现。2019 年后代码停止维护(此后仅有 README 与文档的零星改动)。

现在要让它重新可用,有两条路:在 1.x 基础上逐步现代化,或者用其领域知识重写。

## 现状评估

对 1.x 全部 15 个组件仓库做了逐一分析,结论如下。

**依赖栈已整体 EOL**

Python 2.7、OpenResty 1.11.2(2017 年版,含大量已知 CVE)、Esper 6.1、React 15 + webpack 3(需 Node ≤ 10)、D3 v3、Aerospike、jackson 1.9.13、commons-collections 3.2.1(含经典反序列化利用链)、CentOS 基础镜像。这不是升级某一个组件,而是每一层都需要更换。

**开箱不可运行**

- `nebula_web` / `nebula_query_web` / `nebula_db_writer` 依赖 8 个私有 Python 包,安装脚本从内网源拉取,外网不可达
- `nebula_fe` 依赖的 `BChart-1.1.16.tgz` 不在仓库中,`npm install` 直接失败
- 多个组件启动时要求 `/etc/nebula/` 下的配置文件,缺一个即 `sys.exit(-1)`,而这些配置不在仓库中

**架构层面的历史包袱**

- 自研 RPC 框架(babel)、自研序列化、自研二进制日志格式、自研 LevelDB 索引、自研 Netty HTTP 框架、自研 D3 图表库——这些在 2019 年是因为缺少成熟方案,今天全部有更好的标准件
- 领域模型在 Python 与 Java 各实现一遍并已漂移:元数据层声明支持的条件算子与聚合函数,引擎实际大量未实现,用户配得出来的变量引擎跑不了
- 实时与离线两套计算引擎语义不一致(详见 [ADR-0002](0002-flink-as-unified-engine.md))
- 13 个组件以 git submodule 组织,版本各自漂移

**安全与隐私债务**

代码与配置中存在明文凭据(含一个公网 InfluxDB 的 root 账号)、5 个硬编码的免登录内部 token、无盐单次 SHA1 的口令哈希,以及多处真实客户与终端用户的个人信息残留。

## 决策

**采用全新代码库重写,只继承领域资产,不继承任何实现代码。**

继承的内容:

- 17 个事件模型及 `HTTP_DYNAMIC` 的 30 个基础字段
- 253 个统计变量定义与命名规范
- 170 条策略模板
- 15 个风险标签
- `decision` / `scene` / `check_type` 三组枚举
- `/checkRisk` 对外契约

不继承的内容:全部实现代码、自研基础设施、存储格式、构建与部署脚本。

## 理由

**领域资产与实现代码的价值差距悬殊。** 那 253 个变量和 170 条策略是多年风控对抗经验的沉淀,重新设计要花数年;而实现代码在今天的技术条件下重写,反而比改造更快、结果更好。

**逐步升级的路径实际上不存在。** 每一层依赖都需要更换,组件之间又通过自研 RPC 紧耦合,不存在"先换存储再换计算"这样可以分步验证的切分。逐步升级会退化成"一边重写一边维护两套",成本高于直接重写。

**git 历史无法清洗。** 已泄露的凭据与客户数据存在于历史提交中。若在原仓库上继续开发,新产品将永久背负一个"历史中含敏感信息"的代码库。新仓库从第一个 commit 起即为干净状态。

## 代价

- 1.x 用户没有原地升级路径,必须并行部署并迁移资产
- 已有的 380+ fork 无法直接受益
- 短期内没有可用版本(1.x 虽然停更但至少有完整实现)

## 缓解

- 提供 `nebula-migrate` 工具完成资产迁移,并在[迁移指南](../migration/from-1x.md)中逐条说明 6 处语义差异
- 保持对外契约兼容,业务系统的接入代码无需改动
- 1.x 仓库保持公开并归档,README 顶部指向 2.0

## 关于品牌延续

2.0 使用新仓库 `nebula2`,不在 1.x 仓库上更新。归档后的 1.x 仓库保持公开,保留其 star 与历史作为项目沿革的一部分,并通过 README 顶部的醒目链接导流至 2.0。待 2.0 发布稳定版后,可考虑将 1.x 更名为 `nebula-legacy`、2.0 承接 `nebula` 主名——GitHub 会自动处理重定向。
