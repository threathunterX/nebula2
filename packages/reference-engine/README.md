# reference-engine —— 算子语义的参考实现

一个**可运行**的最小引擎,直接消费 `seeds/` 下经过 schema 校验的资产,把事件流跑成风险告警。

它不是产品的一部分,不追求性能,也不会进入生产部署。它的作用有三个:

1. **验证[算子语义规格](../../docs/reference/operators.md)自洽。** 规格里"空窗口返回什么""null 怎么处理""值相等时怎么排序"这类规定,只有真的实现一遍才知道有没有漏洞或歧义。
2. **为 [golden 回归测试](../../tests/golden/)生成基线。** 输出确定可复现,同一批合成事件永远得到同一批告警。
3. **给 Java 引擎实现一个可对照的参照物。** 实现分歧时,先看这里怎么做的,再看规格怎么写的。

## 运行

```bash
cd packages/reference-engine

# 跑撞库场景,加载全部 170 条策略与 253 个变量
node run.js

# 爬虫场景
node run.js --scenario crawler

# 只跑一条策略
node run.js --strategy "IP多次登录失败"

# 输出完整告警 JSON
node run.js --strategy "IP多次登录失败" --json

# 规格符合性测试
node --test 'test/*.test.js'
```

无外部依赖,只用 Node 内置模块。

## 结构

| 文件 | 内容 |
|---|---|
| `src/operators.js` | 聚合算子。对应规格 §2,每个算子的注释标注了它实现的是哪一条规定 |
| `src/hll.js` | HyperLogLog(log2m=14),去重计数的近似模式 |
| `src/conditions.js` | 过滤与比较算子。对应规格 §3 |
| `src/windows.js` | 窗口模型:滑动、滚动、无界,以及迟到判定。对应规格 §4 |
| `src/cel.js` | CEL 求值(仅覆盖内置资产用到的子集) |
| `src/variables.js` | 变量计算图:依赖闭包、拓扑排序、六类节点。对应规格 §1 |
| `src/events.js` | 事件模型与单继承链 |
| `src/engine.js` | 策略求值、内联计数器、延迟策略、告警去重与产出 |
| `src/scenario.js` | 合成事件生成器,固定随机种子 |
| `test/` | 规格符合性测试,测试名标注了规格出处 |

## 它发现了什么

写这个实现的直接产出不只是代码,还有几处**规格与数据的问题**:

**规格的一处欠定义。** 迟到检测的测试一开始失败了,因为实现把水位线放在了每个 key 的窗口状态里。查下来发现规格只写了"allowedLateness 之内的迟到事件仍会更新窗口",没说水位线的作用域。正确语义是**流级**——否则每个新 key 的首个事件都不可能被判为迟到,攻击者可以用不断变化的 key 绕过检测。规格已补入该条。

**又一处规格欠定义:事件继承。** 事件模型是单继承的(`ACCOUNT_LOGIN` 的父事件是 `HTTP_DYNAMIC`),因此一条登录事件同时也是一条动态请求事件。但规格没写明「按事件名匹配」时是否要考虑继承链。实现之初没考虑,结果定义在父事件上的变量与策略永远不会被触发 —— 触发匹配必须走整条继承链。

**实证确认了两处 1.x 数据缺陷。** 这两处此前是静态分析发现的,跑起来后看到了实际后果:

- 含未配置占位符的策略(`IP请求登录前未访问必要资源` 等)在 160 条事件的场景里产生 84 条告警,把 40 个正常用户全打中了。它们判定"访问某页面的次数 == 0",而占位页面不存在,条件恒真。这解释了为什么 `seeds/INVENTORY.md` 要把这批策略单独标记 🔧。
- `IP集中请求登录` 写入名单的主体是设备号而非 IP,`设备集中请求登录` 反之。策略名与实际行为不符。

这些都固化成了 `test/engine.test.js` 里的回归测试。

## 与生产引擎的关系

生产引擎(`apps/engine/`,基于 Flink)在这几个方面必然不同:

| | 参考实现 | 生产引擎 |
|---|---|---|
| 状态 | 进程内存 | RocksDB + Checkpoint |
| 滑动窗口 | 保留原始事件,取值时重算 | 增量聚合 |
| 迟到事件 | 计数 | 侧输出流,可落盘审计 |
| 变量图 | 完整 DAG,按策略引用构建依赖闭包 | 同左,但按 key 分区并行调度 |
| 并行 | 单线程 | 按 key 分区并行 |
| CEL | 极简子集 | 标准 cel-java |

**语义必须一致**,实现可以不同。两者的差异由 golden 测试守住。
