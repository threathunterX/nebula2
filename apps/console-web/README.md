# console-web —— 管理界面

策略管理、告警查询、变量浏览。React 19 + TypeScript + Vite。

替代 1.x 的 `nebula_fe`(React 15 + webpack 3)。

## 状态

| 能力 | 状态 |
|---|---|
| 登录(HTTP Basic,凭据只在内存) | ✅ |
| 概览:资产统计 + 告警趋势 | ✅ |
| 策略列表(分类 / 状态 / 名称过滤) | ✅ |
| 策略详情、状态切换、定义编辑、修订历史 | ✅ |
| 告警查询(时间范围、处置、主体) | ✅ |
| 变量浏览(模块 / 敏感级别过滤) | ✅ |
| 账号与令牌管理 | 🚧 |
| 策略的可视化编辑器(当前是 JSON 文本框) | 🚧 |
| 图表(当前是纯 CSS 柱状图) | 🚧 |

## 跑起来

需要控制面已在 `http://127.0.0.1:8080` 运行(见 [Lite 部署](../../deploy/compose/))。

```bash
cd apps/console-web
npm install
npm run dev          # http://localhost:5173
```

开发服务器把 `/api` 与 `/actuator` 代理到控制面,前端不处理跨域。要指向别的地址:

```bash
NEBULA_API=http://其他主机:8080 npm run dev
```

构建产物是**纯静态文件**,由控制面或任意静态服务器托管 —— 前端不引入自己的运行时:

```bash
npm run build        # -> dist/
```

## 几个刻意的选择

**不引入 UI 框架。** 这个界面的组件种类很少(表格、表单、几个徽章),一个 CSS 变量表
就够了。少一个前端依赖,私有化部署就少一份要审计的东西 —— 采集器零外部依赖、参考引擎
零外部依赖,前端也按同一个标准来。当前全部生产依赖只有 React 与 react-router。

**凭据只保存在内存,不写 localStorage。** 存进去意味着任何拿到 XSS 的人都能直接读走
一个管理员口令。代价是刷新页面即登出,这是刻意的取舍。

**登录时先验证凭据再放行。** 用一个最轻的已认证接口试一次,而不是「先让进去再说」——
后者会让口令错误直到第一次真正操作时才暴露。

**401 与 403 分开提示。** 前者是没登录或口令错,后者是登录了但当前角色不该做这件事。
混为一谈会让人反复重登却始终不成功。

**空状态要说清楚「为什么空」。** 告警查不到时不写「暂无数据」,而是提示按接入指南的
四步倒推 —— 接入初期告警为 0 是正常的,内置阈值来自 1.x 当年某个站点,多半需要按自己
的流量校准。只显示「暂无数据」会让人分不清是没风险还是没接通。

## 策略编辑

当前是 JSON 文本框,不是可视化编辑器。保存时:

- 带上读到的**行版本**做乐观并发,冲突返回 409 而不是静默覆盖
- 服务端按 schema 与引用完整性校验,不通过时一次列出全部问题,界面原样展示
- 每次保存记入修订历史与审计日志

> **行版本 ≠ 领域模型版本。** 详情接口顶层的 `version` 是行版本(乐观并发用),
> `definition.version` 是领域模型版本(当前恒为 `"2.0"`)。这个界面是第一个真实客户端,
> 它一上来就把两者搞混了 —— 详情接口当时根本没返回行版本,导致 PUT 稳定 409。
> 接口已修正为顶层返回行版本,见 [API 参考](../../docs/reference/api.md)。
